# キャリア実績 日次入力ツール（GAS版）

携帯ショップの店舗実績（MB総販・MNP・副商材・屋号商材）を毎日入力するための
Web アプリです。Google スプレッドシート ＋ Google Apps Script (GAS) だけで動き、
外部サービスやサーバーは一切不要です。

- スマホ・PCのブラウザから開ける入力フォームに入力→保存すると、その場で
  スプレッドシートに書き込まれます。
- 週次・月次の集計シートは**保存するたびに自動更新**されます。
- 「今週の報告テキストをコピー」「当月をCSVで書き出す」「報告をメール送信」
  などのボタンも用意しています。

GAS が初めての方でも迷わないように、この README は**上から順に番号どおり
進めるだけ**で使えるように書いています。

---

## 0. 全体の流れ（まずここだけ読めばOK）

1. Google スプレッドシートを新規作成する
2. スクリプトエディタに `dist/コード.gs` の中身を貼る
3. HTMLファイルを追加して `dist/フォーム.html` の中身を貼る
4. マニフェスト(`appsscript.json`)でタイムゾーンを確認する
5. `初期セットアップ` を実行する（5つのシートが自動で作られる）
6. Web アプリとしてデプロイし、URLを取得する
7. スマホのホーム画面に追加する

以下、それぞれを詳しく説明します。

---

## 1. スプレッドシートを新規作成する

1. ブラウザで https://sheets.new を開く（Googleアカウントでログインしておく）
2. 左上のタイトルを「〇〇店 日次実績」など分かりやすい名前に変更する
3. このスプレッドシートが、以後すべてのデータの保存先になります

---

## 2. スクリプトエディタを開き、コードを貼り付ける

1. スプレッドシートのメニューから **拡張機能 → Apps Script** を選ぶ
   （新しいタブでスクリプトエディタが開きます）
2. 左側のファイル一覧にある `コード.gs`（最初から入っている空のファイル）を開く
3. 中身を全選択して削除し、このリポジトリの **`dist/コード.gs`** の中身を
   すべてコピーして貼り付ける
4. 左側のファイル一覧の `+` → **HTML** を選び、ファイル名を **`フォーム`**
   （拡張子 `.html` は自動で付きます。**「フォーム」という名前にすること**が
   重要です。コード側で `HtmlService.createTemplateFromFile('フォーム')`
   という名前を指定しているためです）
5. 作成された `フォーム.html` の中身を全部削除し、このリポジトリの
   **`dist/フォーム.html`** の中身をすべてコピーして貼り付ける
6. 上部の保存アイコン（フロッピーディスクの絵）をクリックして保存する

---

## 3. タイムゾーンを確認する（Asia/Tokyo）

このツールは日付をすべて `Asia/Tokyo` 前提で計算します。ズレを防ぐため、
念のため手動でも確認してください。

1. スクリプトエディタの左メニューから **プロジェクトの設定**（歯車アイコン）を開く
2. 「`appsscript.json` マニフェスト ファイルをエディタで表示する」に
   チェックを入れる
3. ファイル一覧に `appsscript.json` が表示されるので開き、
   `"timeZone": "Asia/Tokyo"` になっていることを確認する
   （このリポジトリの `appsscript.json` をそのまま貼ってももちろん構いません）

---

## 4. 初期セットアップを実行する

1. スクリプトエディタ上部の関数選択プルダウンから **`初期セットアップ`** を選ぶ
2. **実行**ボタン（▷）をクリックする
3. 初回は「承認が必要です」という画面が出るので、以下の手順で進める
   1. 「権限を確認」をクリック
   2. 自分のGoogleアカウントを選択
   3. 「このアプリは Google で確認されていません」と出た場合は
      「詳細」→「（プロジェクト名）に移動（安全ではないページ）」を選ぶ
      （※これは自分自身が作ったスクリプトを自分に許可しているだけなので問題ありません）
   4. 「許可」をクリック
4. 実行が完了すると、スプレッドシートに以下の5つのシートが自動生成されます
   - 日次ログ／日次サマリー／週次集計／月次集計／設定
5. 「設定」シートを開き、**F列・G列の「報告メール宛先」**と、
   **A〜D列の「稼働人数」**（例：`7人`、`4+1人` のように自由入力）を必要に応じて入力する

> 補足：`初期セットアップ` は**何度実行しても既存の日次ログのデータは消えません**。
> 項目を増やした後の再実行も安全です（詳しくは9章）。

---

## 5. Web アプリとしてデプロイする

1. スクリプトエディタ右上の **デプロイ → 新しいデプロイ** をクリック
2. 「種類の選択」の歯車アイコンから **ウェブアプリ** を選ぶ
3. 説明欄に「日次入力フォーム」などと入力
4. 「次のユーザーとして実行」→ **自分** を選択
5. 「アクセスできるユーザー」を選ぶ（誰と共有するかで選ぶ）
   - 自分だけで使う → **自分のみ**
   - 店舗スタッフ全員に使わせる（Googleアカウントでログインしている人なら誰でも）
     → **全員**
   - 社内(Google Workspace)限定 → **（組織名）内のユーザー**
6. **デプロイ** をクリックし、表示された **ウェブアプリのURL** をコピーする
   （これが日々使う入力フォームのURLです。ブックマークしておいてください）

> 共有範囲を後から変更したい場合は、デプロイ → デプロイを管理 → 編集(鉛筆アイコン)
> から「アクセスできるユーザー」を変更し、再デプロイしてください。

## 6. スマホのホーム画面に追加する

### iPhone (Safari)
1. コピーしたURLをSafariで開く
2. 下部の共有アイコン（□に↑）をタップ
3. 「ホーム画面に追加」を選ぶ

### Android (Chrome)
1. コピーしたURLをChromeで開く
2. 右上の「⋮」メニューをタップ
3. 「ホーム画面に追加」を選ぶ

これで、アプリのように1タップで日次入力フォームを開けるようになります。

## 7. 使い方

1. フォームを開く（日付は今日の日付が自動で入っています）
2. 過去の日付を選び直すと、すでに入力済みならその日の値が自動で読み込まれ、
   「入力済み → 上書き保存になります」と表示されます
3. タブ「① MB総販・MNP」「② 副商材」「③ 屋号商材」に数字を入力していく
   （入力するたびに右側／下部の自動計算パネルにその日の3区分シェア率が
   リアルタイムで表示されます）
4. 「保存」を押すと、その場でスプレッドシートに反映されます
   （保存後は、その日を含む週の実績も画面に表示されます）
5. 週末や月末には「今週の報告テキストをコピー」「今月の報告テキストをコピー」
   ボタンでLINEやSlackにそのまま貼れる文章を取得できます
6. 「この月をCSVで書き出す」で当月の日次ログをExcelなどで開けるCSVとして
   ダウンロードできます
7. 「報告をメール送信」を押すと、「設定」シートに登録したメールアドレスへ
   今週の報告テキストが送信されます（宛先未設定のときはその旨が画面に表示されます）

---

## 8. スプレッドシートの構成

| シート名 | 役割 |
|---|---|
| 日次ログ | 生データ（1日1行、日付をキーに上書き保存） |
| 日次サマリー | 日次ログを見出し名で参照した数式による自動集計（1日1行） |
| 週次集計 | 月曜起算の週ごとのブロック集計（保存の都度、自動で作り直される） |
| 月次集計 | 月ごとの週ブロック＋月合計＋シェア率推移グラフ・構成比円グラフ |
| 設定 | 稼働人数（適用開始年月で履歴管理）・報告メール宛先 |

## 9. 項目を増やしたいとき

このツールは「見出し名（ラベル文字列）」から列位置を解決する設計になっているため、
**定義を1行追加するだけ**で、シートの列・入力フォーム・報告テキスト・CSVすべてに
自動で反映されます。列番号を直接書き換える必要は一切ありません。

編集する場所は `src/logic.js` の冒頭コメントと `dist/コード.gs` の冒頭コメントに
書いてあるとおりです。

| 増やしたいもの | 編集する場所 |
|---|---|
| 副商材の項目 | `Logic.SUB_DEF` 配列に1行追加（`type:'input'`）。小計を増やす場合は `type:'sum'` の行を追加し `of` に集計対象の `key` を並べる |
| 屋号商材 | `Logic.YAGOU_PRODUCTS` 配列に1行追加 |
| MNP移転元の選択肢 | `Logic.SOURCES` 配列に1行追加 |

手順：

1. `src/logic.js` を編集する
2. `node test/run.js` を実行し、既存のテストが壊れていないことを確認する
3. `node build.js` を実行して `dist/コード.gs` を再生成する
4. スクリプトエディタの `コード.gs` の中身を、生成し直した `dist/コード.gs` の
   中身で丸ごと置き換えて保存する（`フォーム.html` も変更した場合は同様に置き換える）
5. スクリプトエディタで **`初期セットアップ`** を再実行する
   （既存の日次ログのデータは消えません。新しい列は空欄＝0件として追加されます）

## 11. トラブルシューティング（既知の落とし穴と対処法）

このツールを作る過程で実際に発生した不具合と、その対策済みの内容です。
同じ症状が出た場合の切り分けに使ってください。

### `Exception: 固定されている列と固定されていない列は結合できません。`
日次ログの1行目（大分類の結合セル）が、固定列（A列＝日付）の境界を
またいで結合されようとすると発生します。本ツールでは「日付」を単独の
大分類にし、結合範囲が固定列をまたがないことを `Logic.validateMergeRanges`
で必ずチェックしてから結合するようにしているため、通常は発生しません。
もし手動でシートの列を並べ替えて発生した場合は、`初期セットアップ` を
再実行してシート構成を作り直してください（データは消えません）。

### 日付が `Invalid Date` になる／同じ日付なのに行が増えていく
スプレッドシートは日付らしき文字列を自動的に日付型のセルに変換すること
があります。本ツールは日次ログのA列（日付）をあらかじめ書式なしテキスト
（`setNumberFormat('@')`）にしたうえで書き込み、読み込み時も必ず
`Logic.toDateStr()` を通して `yyyy-MM-dd` の文字列に正規化しています。
それでも同様の症状が出た場合は、A列のセル書式が「自動」や「日付」に
変わっていないか確認し、`初期セットアップ` を再実行してください。

### 新しいシートで `getRange` がエラーになる（列が足りない）
日次ログは67列前後、日次サマリーは26列超になりますが、Googleスプレッド
シートの新規シートは既定で26列しかありません。本ツールは書き込み前に
必ず `ensureGridSize()` で必要な行列数を確保してから書き込むため、
通常は発生しません。

### 項目を1つ増やしたら他の集計がおかしくなった
列番号を直接指定していると起こる典型的な不具合です。本ツールは
`getColMap()` で**見出し名（ラベル文字列）から列位置を解決**しており、
配列の途中に項目を追加しても既存の参照は壊れません。もし見た目が
崩れた場合は、見出しのラベル文字列自体を変更していないか確認してください
（ラベルの文字列そのものが「識別子」の役割を持っています）。

### `初期セットアップ` を再実行したら日次ログのデータが消えた
本ツールは再実行時、既存データを見出し名（ラベル）をキーに一度メモリへ
退避し、新しい列順に並べ直してから書き戻すことでデータ消失を防いでいます。
もし消えてしまった場合は、直前にスプレッドシートの「変更履歴」
（ファイル → 変更履歴を表示）から復元できることがあります。

### エラーの行番号が実際の原因と違う場所を指している
GAS はシートへの読み書きをある程度まとめて後から実行するため、
**エラーメッセージに表示される行番号は、実際に原因となった処理とは
違う関数・違う行を指すことがあります**。エラーが出た関数だけでなく、
その前後で `SpreadsheetApp` を呼んでいる処理（特に直前に実行した
関数）も含めて確認してください。

### 「スクリプト関数が見つかりません: 初期セットアップ」と出る
`dist/コード.gs` の中身を貼り付けたファイル名が `コード.gs` になって
いるか、貼り付けが最後まで行われているか（ファイルの末尾が
途中で切れていないか）を確認してください。

### `フォーム.html` が見つからないというエラーが出る
HTMLファイルの名前が **完全に「フォーム」** になっているか確認してください
（`フォーム (1)` のような名前になっていると `doGet()` から参照できません）。

### 「ロックを取得できませんでした」と出る
複数人がほぼ同時に保存しようとした場合に `LockService` が排他制御のために
発生させるものです。数秒待って保存し直してください。

### メールが送信されない
「設定」シートのF列に `報告メール宛先(カンマ区切り)` という行があるか、
その右側(G列)にメールアドレスが入力されているか確認してください。
複数宛先はカンマ区切りで入力します（例：`a@example.com,b@example.com`）。

## 12. データ・業務ルールの前提

- キャリアは5つ：DCM／SB／YM／au／UQ。集計・シェア率は3区分
  （DCM／SB・YM／AU・UQ）に統合します
- MB総販（機変＋純新規＋MNP）は入力させず自動計算します
- MNPは「リク込み」（入力値）／「リク除き」（リク込みから同一グループ内の
  番号移行を控除した値・自動計算）／「内SIMのみ」（リク込みの内数・入力値）
  の3つの見方があります。DCMには同一グループ内移行の概念がないため、
  DCMは常に「リク込み＝リク除き」です
- 数値は常に非負整数として扱います。空欄は0、マイナスは0に丸められます
  （クライアント側だけでなく、サーバー側でも必ず丸め直しています）

## 13. ローカルでのテスト

集計ロジック（`src/logic.js`）とシート生成・保存処理（`src/sheets.js`、
`SpreadsheetApp` の軽量モック経由）は、スプレッドシートを開かなくても
ローカルで検証できます。

```bash
node test/run.js
```

MB総販の内訳計算、MNPリク除きのグループ控除、週の月曜起算・日曜が
前週に入る境界、報告テキストの0件省略、全ゼロ時に0除算にならないこと、
列マップの見出し名解決、大分類の結合範囲が固定列をまたがないこと、
初期セットアップの再実行でデータが消えないこと、などを検証しています。
